# 蓝牙开机自启动初始化流程

## 目标

设备上电后自动进入 BLE NUS 服务，手机无需通过串口或 Shell 手动启动蓝牙。BLE 启动失败不能影响电机安全控制、CAN 通信或 M55 推理链路。

## 启动顺序

1. RT-Thread 组件初始化执行 `m33_ble_gate_init()`，创建 `blegate` 互斥锁并初始化 BLE 诊断状态。
2. `main()` 执行 `m33_init_framework()`：先创建 M55 IPC 异步初始化线程，再初始化传感器、输入缓冲、控制管理、CAN 和安全系统。
3. `main()` 调用 `m33_ble_runtime_auto_start()`，仅创建静态 `ble_boot` 线程，不在主线程直接启动协议栈。
4. `ble_boot` 延迟 3 秒，等待控制链路和底层外设稳定后，依次执行 BLE 服务初始化、服务线程启动、HCI 传输初始化和 HCI 启动。
5. 启动结果写入 BLE gate 诊断状态并打印 `[ble] auto start ret=<ret>`。手机仅在 HCI 状态为 `READY` 后连接。

## 可靠性约束

- 启动线程使用静态 2 KB 栈，避免动态分配失败和启动期堆碎片。
- gate 互斥锁串行化自动启动与 Shell 手动启动，已就绪时重复请求直接返回成功。
- 自动启动只尝试一次。失败状态保留给 `m33_ble_status` 和 `m33_ble_diag` 查询，不进行高频重试，避免已知的协议栈重复初始化和 HardFault 风险。
- BLE 不参与电机使能；BLE 不可用时，CAN、M55 推理和安全控制仍按各自初始化路径运行。

## 上电验收

上电后等待至少 5 秒，在 M33 Shell 执行：

```text
m33_ble_status
m33_ble_diag
cmd_control_debug
cmd_m55_emg_status
```

预期日志包含 `[ble] auto start ret=0`，BLE gate 与 HCI 状态进入 `READY`。同时 `cmd_control_debug` 的 F103 `sensor` 计数应继续增长，证明 BLE 启动未阻塞传感器上报。

若自动启动失败，保留串口日志和上述两条 BLE 诊断输出；不得在未定位错误前循环执行 `m33_ble_start`。
