# 康复机械臂 Linux 仿真主机完整部署指南

## 1. 文档目标

本文用于把康复机械臂 ROS2、MuJoCo、6DOF 模型、轨迹规划工具部署到一台新的 Linux 电脑。部署完成后，新电脑应能独立从 GitHub 构建和运行，不再依赖旧的 `192.168.3.34` 主机目录。

目标部署环境：

- 仓库：`ChillAmnesiac/Medical-Rehabilitation-Manipulator`
- 分支：`feature/rehab-arm-ros2-architecture`
- 已验证提交：`516f09bb1dd94a2e3ac1bcaeb5bf71b9407f1330`
- 系统：Ubuntu 22.04 x86_64
- ROS2：Humble
- Python：3.10
- MuJoCo：Python `mujoco` 模块
- ROS 域：`ROS_DOMAIN_ID=42`

版本说明：提交 `516f09bb` 已在旧主机的 Ubuntu 24.04 + ROS2 Jazzy 环境完成测试；仓库构建脚本和部署启动脚本同时支持 ROS2 Humble。Ubuntu 22.04 目标机必须重新执行本文第 7、8、12 节，验收通过后才能连接 NanoPi。不要在同一部署环境中混用 Humble 与 Jazzy。

部署后包含：

- `rehab_arm_description`：URDF、6DOF schema 与临时标定配置。
- `rehab_arm_sim_mujoco`：MuJoCo 后端、6DOF MJCF 模型、纯仿真和硬件 shadow。
- `rehab_arm_control`：笛卡尔 IK、关节轨迹规划、MuJoCo plan node。
- `rehab_arm_psoc_bridge`：NanoPi/PSOC 数据协议、目标编码和安全门工具。
- `rehab_arm_bringup`：组合启动入口。

## 2. 安全边界

部署和首次验收必须遵循以下边界：

1. 首次启动只运行环境检查和纯 MuJoCo shadow。
2. 环境检查不会打开 CAN，不会发送 `0x320/0x321`，不会控制 M33 或电机。
3. 纯 MuJoCo shadow 只使用：
   - 输入：`/sim/medical_arm/joint_trajectory`
   - 输出：`/sim/medical_arm/joint_states`
4. 不得把首次测试轨迹发布到 `/arm_controller/joint_trajectory`。
5. `medical_arm_6dof_hardware_shadow.launch.py` 用于读取硬件状态并映射到仿真，不代表获得真实运动权限。
6. 真实电机控制必须继续经过 M33 的限位、反馈新鲜度、故障、急停和模式状态机。

## 3. 系统准备

### 3.1 基础软件

```bash
sudo apt update
sudo apt install -y \
  git build-essential curl gnupg lsb-release \
  python3 python3-pip python3-venv python3-pytest \
  python3-colcon-common-extensions python3-rosdep \
  libgl1-mesa-dev libegl1-mesa-dev
```

### 3.2 ROS2 Humble

先按 ROS2 官方 Ubuntu 22.04 安装流程配置软件源：

`https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debs.html`

然后安装：

```bash
sudo apt update
sudo apt install -y ros-humble-ros-base
```

验证：

```bash
source /opt/ros/humble/setup.bash
echo "$ROS_DISTRO"
ros2 --help >/dev/null
```

预期 `ROS_DISTRO` 为 `humble`。如果显示为 `jazzy` 或其他版本，应先清理当前终端环境，不要继续构建。

### 3.3 rosdep

```bash
sudo rosdep init 2>/dev/null || true
rosdep update
```

### 3.4 MuJoCo

在专用仿真主机上，将 MuJoCo 安装到当前用户的 Python 3.10 环境：

```bash
python3 -m pip install --user mujoco
python3 -c "import mujoco; print(mujoco.__version__)"
```

无显示器或远程运行时使用 EGL：

```bash
export MUJOCO_GL=egl
```

如果显卡/EGL 不可用，可临时改为：

```bash
export MUJOCO_GL=osmesa
```

## 8. MuJoCo 无动作启动验收

使用独立 ROS 域，避免干扰现场系统：

```bash
cd "$HOME/Medical-Rehabilitation-Manipulator/rehab_arm_ros2_ws"
source /opt/ros/humble/setup.bash
source install/setup.bash
export ROS_DOMAIN_ID=99
export MUJOCO_GL=egl

timeout --signal=INT 8s \
  ros2 launch rehab_arm_sim_mujoco medical_arm_6dof_shadow.launch.py
```

正常日志应包含：

```text
Rehab arm simulation ready, backend=mujoco-model,
joint_profile=medical_arm_6dof,
joint_state_topic=/sim/medical_arm/joint_states,
trajectory_topic=/sim/medical_arm/joint_trajectory
```

超时后进程应通过 SIGINT 干净退出。

再次确认没有硬件输出：

```bash
ros2 topic list | grep '^/sim/medical_arm/'
```

## 9. ROS2 局域网配置

创建：

```bash
cat > "$HOME/.rehab_arm_ros2_network" <<'EOF'
export ROS_DOMAIN_ID=42
export ROS_LOCALHOST_ONLY=0
export MUJOCO_GL=egl
EOF
```

加载并检查：

```bash
source "$HOME/.rehab_arm_ros2_network"
env | grep -E 'ROS_DOMAIN_ID|ROS_LOCALHOST_ONLY|MUJOCO_GL'
```

NanoPi、仿真主机和调试电脑必须：

- 位于可互通的局域网。
- 使用相同 `ROS_DOMAIN_ID=42`。
- 系统时间基本一致。
- 防火墙不阻断 DDS 发现和数据通信。

Humble 使用默认 DDS 子网发现，不依赖 `ROS_AUTOMATIC_DISCOVERY_RANGE`。最好让 NanoPi 与仿真主机使用相同 ROS2 发行版；如果 NanoPi 仍运行 Jazzy，必须额外验证实际使用的 topic 类型和 QoS，不能仅凭节点可见就认为通信兼容。

跨主机检查：

```bash
ros2 node list
ros2 topic list | grep -E 'rehab_arm|medical_arm|joint_states'
```

## 10. 手动运行

### 10.1 纯 6DOF MuJoCo shadow

```bash
source /opt/ros/humble/setup.bash
source "$HOME/.rehab_arm_ros2_network"
source "$HOME/Medical-Rehabilitation-Manipulator/rehab_arm_ros2_ws/install/setup.bash"

ros2 launch rehab_arm_sim_mujoco medical_arm_6dof_shadow.launch.py
```

### 10.2 硬件状态 shadow

只有在 NanoPi 的 `/joint_states` 已验证且不需要真实运动时使用：

```bash
ros2 launch rehab_arm_sim_mujoco \
  medical_arm_6dof_hardware_shadow.launch.py
```

它将硬件状态映射到完整 6DOF 仿真目标。当前明确映射包含：

```text
forearm_rotation_joint -> jian_xuanzhuan_joint
```

未连接关节使用显式占位位置，不得据此推断真实关节已经标定。

## 11. systemd 开机自启动

### 11.1 安装启动脚本和服务文件

```bash
cd "$HOME/Medical-Rehabilitation-Manipulator"

sudo install -m 0755 \
  deploy/scripts/start_sim_host_medical_arm_shadow.sh \
  /usr/local/bin/start_sim_host_medical_arm_shadow.sh

sudo install -m 0644 \
  deploy/systemd/rehab-arm-sim-host-shadow.service \
  /etc/systemd/system/rehab-arm-sim-host-shadow.service
```

仓库模板默认用户是 `cal`。在新电脑上必须替换用户名和工作区：

```bash
SIM_USER="$USER"
SIM_HOME="$HOME"
SIM_WORKSPACE="$HOME/Medical-Rehabilitation-Manipulator/rehab_arm_ros2_ws"

sudo sed -i \
  -e "s|^User=.*|User=$SIM_USER|" \
  -e "s|^Environment=WORKSPACE=.*|Environment=WORKSPACE=$SIM_WORKSPACE|" \
  -e "s|^Environment=ROS_NETWORK_ENV=.*|Environment=ROS_NETWORK_ENV=$SIM_HOME/.rehab_arm_ros2_network|" \
  /etc/systemd/system/rehab-arm-sim-host-shadow.service
```

检查最终文件：

```bash
systemd-analyze verify /etc/systemd/system/rehab-arm-sim-host-shadow.service
grep -E '^(User|Environment|ExecStart)=' \
  /etc/systemd/system/rehab-arm-sim-host-shadow.service
```

### 11.2 启用服务

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now rehab-arm-sim-host-shadow.service
```

检查：

```bash
systemctl is-enabled rehab-arm-sim-host-shadow.service
systemctl is-active rehab-arm-sim-host-shadow.service
systemctl status rehab-arm-sim-host-shadow.service --no-pager
journalctl -u rehab-arm-sim-host-shadow.service -n 100 --no-pager
```

预期为 `enabled`、`active`，日志包含 `Rehab arm simulation ready`。

## 15. 常见问题

### 15.1 找不到 `setup.bash`

现象：

```text
ROS workspace install setup not found
```

处理：

```bash
cd "$HOME/Medical-Rehabilitation-Manipulator/rehab_arm_ros2_ws"
source /opt/ros/humble/setup.bash
./build_ros2.sh
```

### 15.2 `ModuleNotFoundError: mujoco`

```bash
python3 -m pip install --user mujoco
python3 -c "import mujoco; print(mujoco.__version__)"
```

确保安装 MuJoCo 的用户与 systemd 的 `User=` 相同。

### 15.3 EGL 初始化失败

```bash
export MUJOCO_GL=osmesa
ros2 run rehab_arm_sim_mujoco check_sim_env.py
```

如果 OSMesa 可运行但 EGL 不可运行，检查显卡驱动和 `/dev/dri` 权限。

### 15.4 ROS2 看不到 NanoPi

在两台机器分别检查：

```bash
echo "$ROS_DOMAIN_ID"
echo "$ROS_LOCALHOST_ONLY"
ip addr
```

两端应使用 `ROS_DOMAIN_ID=42`，并能互相 `ping`。

### 15.5 systemd 不断重启

```bash
journalctl -u rehab-arm-sim-host-shadow.service -n 200 --no-pager
grep -E '^(User|Environment|ExecStart)=' \
  /etc/systemd/system/rehab-arm-sim-host-shadow.service
```

重点检查：用户、仓库路径、`install/setup.bash`、网络环境文件和 MuJoCo Python 安装位置。

### 15.6 修改代码后运行的还是旧版本

```bash
cd "$HOME/Medical-Rehabilitation-Manipulator/rehab_arm_ros2_ws"
rm -rf build install log
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```
